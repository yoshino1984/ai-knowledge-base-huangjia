# AI 知识库 · 项目愿景 v1.0

## 要做什么

- 每天或按需采集 AI/LLM/Agent 相关技术动态，优先覆盖 GitHub Trending、Hacker News、RSS 技术源。
- 用多 Agent 流程完成采集、分析、整理、发布：collector 负责找资料，analyzer 负责判断价值，organizer 负责归档成知识条目。
- 输出结构化知识条目，供后续检索、Bot 问答、定时推送和复盘使用。
- 保留从 V1 到 V4 的演进路径：先手动跑通，再自动化，再多 Agent 工作流，最后上线分发。
- V1 默认采集规模：GitHub 15 条、Hacker News 10 条、RSS 10 条。
- 知识条目最终以 JSON 为主，方便后续自动化校验、检索、Bot 查询和分发。

## 不做什么

- 不把参考答案目录 `v1-skeleton/`、`v2-automation/`、`v3-multi-agent/`、`v4-production/` 当作我们的实现成果。
- 不追求一开始就全自动上线，先完成可验证的本地闭环。
- 不采集与 AI/LLM/Agent 明显无关的泛技术内容，除非它对 AI 工程实践有直接价值。
- 不编造项目、指标、摘要或来源链接。
- V1 不纳入 arXiv，先聚焦工程信息源。arXiv 作为后续扩展项处理。

## 边界 & 验收

- 所有实践产出默认写入 `project/`，过程记录写入 `doc/`。
- 每个知识条目必须能追溯到真实来源链接，包含标题、来源、摘要、标签、评分和时间戳。
- 每个阶段完成后都要能用命令或文件检查验证，而不是只靠口头说明。
- V1 验收：能手动完成采集、分析、整理，并生成第一批知识条目。
- V2 验收：能通过脚本校验 JSON、评分质量，并跑通 pipeline。
- V3 验收：能用工作流表达多 Agent 协作、审核、修正和成本/安全控制。
- V4 验收：能通过 Bot 或分发模块让外部用户读取知识库。
- 评分统一使用 1-10 分。
- 分析维度包括：技术类别、创新点、使用难度。
- `score < 6` 的条目不直接发布，进入待复核队列。

## 怎么验证

- 检查目录结构：`project/` 下存在 specs、agents、skills、knowledge、hooks、pipeline、workflows 等目录。
- 运行采集任务后，`project/knowledge/raw/` 中出现真实来源数据。
- 运行分析任务后，条目包含中文摘要、技术亮点、标签和评分。
- 运行整理任务后，`project/knowledge/articles/` 中出现独立知识条目和索引。
- 使用校验脚本验证 JSON 格式、必填字段和质量分数。
- 每完成一个课程任务，在 `doc/progress.md` 中标记，并说明产出文件。
- 每一节结束后进行一次 Git commit。
