# AI 知识库 · 编码规范 v1.0

## 要做什么

- Python 代码遵循 PEP 8。
- Python 行宽统一为 88，兼容 `black` 默认值。
- 变量、函数、文件名使用 `snake_case`。
- 类名使用 `PascalCase`。
- 公开函数必须有 Google 风格 docstring。
- 公开函数必须写类型注解；内部小函数尽量写类型注解，但 V1 不强制。
- 核心逻辑使用 `logging`，不使用裸 `print()`。
- CLI 入口允许使用 `print()` 输出最终结果或用户可读摘要。
- JSON 文件使用 UTF-8 和 2 空格缩进。

## 不做什么

- 不使用 `import *`。
- 不在代码、日志、文档中输出 API Key、Token、Cookie 等敏感信息。
- 不把参考答案目录中的代码复制为我们的实践实现。
- 不执行危险删除命令。
- 不提交空泛的 `TODO` 或 `FIXME`。允许保留，但必须说明原因和后续动作。

## 边界 & 验收

- 所有实践代码默认写在 `project/` 内。
- 每个脚本失败时必须给出明确错误信息。
- 代码应尽量可测试、可复用，不把核心逻辑写死在命令行入口里。
- V1 不设置测试覆盖率下限，重点是跑通手动闭环。
- V2 开始核心模块测试覆盖率目标为 80%。

## 怎么验证

- 运行 Python 语法检查：`python3 -m py_compile`。
- V1 阶段以 `py_compile` 和手动验证为主。
- V2 阶段正式引入 `black`、`ruff`、`pytest`。
- 后续引入测试后运行 `pytest`。
- 后续引入格式化后运行 `black --check`。
- 后续引入静态检查后运行 `ruff`。
